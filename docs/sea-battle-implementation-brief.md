# Sea Battle web implementation brief

Started November 5, 2026, after the verified Dots and Boxes release. Original web implementation with own art and wording; no Android engine, random-sequence, asset or AI parity is available. Preserve the existing twelve games and browser record keys. Ads stay disabled.

## Rules evidence and chosen variant

Primary source checked November5: Hasbro A3264 instructions, https://instructions.hasbro.com/api/download/A3264_en-us_Battleship-Classic-Board-Game-Strategy-Game.pdf . Browser fetch timed out, but a bounded direct download succeeded. Despite the English URL, the actual four-page file is Spanish/Portuguese. Text extraction and page-one visual inspection establish the10×10 grid, fleet lengths5/4/3/3/2 and orthogonal placement; page two specifies alternating single shots, including after a hit, and victory by sinking the opposing fleet. Local reference: E:/Web App/review-evidence/sea-battle-rules-source-2026-11-05.pdf. No source art/text is copied into the game.

Explicit DoStrike choices: ships may touch side-to-side or diagonally but cannot overlap; all must remain within the board. Hits announce only hit/miss until a ship sinks, when its identity and complete occupied cells are disclosed. This differs from the source edition's identity-on-each-hit rule. No Salvo, extra-turn-on-hit, adjacency exclusion or automatic water marking. A starts; the human can choose either side against the computer. Include local pass-and-play only with deliberate handoff screens that hide the outgoing board before showing the next player's view. This is casual on-device privacy, not protection against inspecting browser storage or code.

## Engine and information boundaries

Stable cells0–99 represent row-major A1–J10. Ships have distinct IDs even for the two length-three pieces. Placement is start cell plus horizontal/vertical orientation, with exact validated lengths. Reject partial/duplicate/out-of-bounds/overlapping fleets before starting; setup permits a validated partial fleet. Invalid shots, repeated coordinates, wrong-side moves and post-victory actions fail without changing state. A hit still changes turns; the final winning hit ends immediately, with no answering shot or draw. Reconstruct saves by validating fleets and replaying the ordered shot cells and players; never trust stored damage, turn, results or revealed ships.

Generator: seeded shuffled legal placements and bounded backtracking, with explicit failure rather than an infinite retry. Touching is allowed. Promise reproducibility, not uniform sampling or equal board difficulty. Keep fleet-placement randomness separate from shot-choice randomness; never pass the opponent fleet seed to an AI decision.

The shooter knowledge object contains only observed miss/hit/sunk marks and fully sunk ship identities/cells. Before sink, neither ship identity nor unhit cells enter it. Computer/hint functions and worker requests take this object only, never a full game state, occupied-cell map, unhit ship positions or fleet-generation seed. Tests must construct distinct hidden fleets with the same observed transcript and demonstrate identical decisions for every level/decision seed.

Easy chooses a seeded unused cell. Medium prioritizes untried orthogonal neighbors of unresolved hits, then a checkerboard hunt with legal fallback. Hard counts individually compatible straight placements for remaining ships, rejects known misses/sunk cells, and prioritizes placements containing unresolved hits. This is a bounded single-ship density heuristic, not an exact full-fleet probability or perfect play. Ships can touch, so a hit cluster must not be silently treated as one ship. Decisions remain legal on every reachable knowledge state and terminate after at most five ships times200 candidate placements; expose an honest reason. Keep the outcome independent of hidden layout.

## Interface, saves and records

Manual placement with ship selection, rotate, clear, legal preview/confirmation, auto-place and a visible five-ship checklist. A new auto-placement cannot silently replace a started game. Keyboard row/column movement, numbered axes, readable ship/shot labels, visible focus and at least44px non-overlapping cell targets. At10×10, scroll inside each board on narrow screens instead of shrinking cells. Own ocean and attack map must be explicitly named; no opponent unsunk positions in visible labels or DOM. Use own SVG/CSS geometry and the established theme.

Default shot preview, confirmation and Escape cancellation; clear hit/miss/sunk announcement, shot history, sunk fleet count, whose turn and terminal winner. Computer/hint work must be cancellable with request/position identity checks and failure/retry feedback. In computer mode Undo returns to the previous human decision, removing that shot and any computer answer; no Undo of initial computer moves before a human has acted. Undo and a delivered usable hint mark assistance. Terminal results freeze Undo. Restart creates a new attempt ID and preserves the original daily identity. Hidden positions may be reviewed only after the result or by explicitly ending the round first.

Saved fleets and legal shot transcript stay in this browser. Result IDs deduplicate; local A/B results cannot inflate computer wins. Track level, human side and assisted/unassisted results separately. A daily uses a date-seeded opposing fleet and fixed Hard opponent; human placement is freely chosen, so it is a reproducible challenge, not a unique puzzle or equal-condition leaderboard. Human A starts the daily. Separate decision seed derives from the public date/shot transcript, not from the secret generator state. Original-date wins only advance daily streaks. Reject malformed dates/settings/history/storage safely.

## Release gate and original explanation

Begin with independent placement geometry/boundary enumeration, many seeded legal fleets, complete reference games with both starting human sides, exact sunk/terminal/turn semantics and immutable rejection. Verify AI legality, bounded work, deterministic choices and hidden-layout invariance. Test actual session replay, paired Undo, malformed/blocked storage, completion dedupe, daily boundaries and worker stale-result cancellation before public UI exposure.

Original guide: actual coordinate placement and hit/sink fixtures, why a hit does not retain the turn, how touching ships invalidate naive cluster assumptions, and a worked density example computed by the implemented heuristic. Distinguish heuristic scores from calibrated probabilities. Keep sourced rule summary concise; own checked examples provide the value. Guide/setup indexable, runtime noindex and excluded from sitemap.

Complete desktop and320px browser games, manual/auto placement, both sides, genuine local handoff if included, save/reload, cancel/undo/retry, keyboard/pointer and no hidden DOM leaks. Lint, TypeScript, production build/prerender, static/live route and guide checks, exact published assets and actual direct trailing-slash runtime behavior must pass. Count the tenth addition only after complete tested publication; no Render deployment for frontend-only work.
