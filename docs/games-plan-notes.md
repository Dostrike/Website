# Website game implementation notes

Surveyed 2026-11-03; companion to game-library-roadmap.md.

- React 18, TypeScript, Vite 5, React Router 7. Lazy game routes in src/App.tsx. Netlify automatically builds main from Dostrike/Website; GitHub commits are the publication mechanism.
- Existing Tic-Tac-Toe/Connect 4 use shared GameSetup and separate match screens. Memory has its own configuration/play screen. Preserve their URLs, rules and stored records. Gomoku uses one route-aware component for /gomoku-setup and /gomoku; add shared abstractions only where actual reuse emerges.
- Theme variables in src/index.css, shared typography/focus and layout in design-system.css, SiteHeader, SiteNavigation and CookieConsent wrap routes. Gomoku reuses these and adds game-scoped CSS. Board intersections stay 44px, with contained horizontal scrolling on narrow screens and arrow-key navigation.
- Optional browser storage must be guarded. Existing last-pick key: dostrike-last-pick. Existing Tic-Tac-Toe daily: dostrike-daily-v1. New Gomoku keys: dostrike-gomoku-records-v1, dostrike-gomoku-session-v1, dostrike-gomoku-daily-v1. Saved moves are replayed through the rules engine on load; malformed/terminal sessions are not continued. Records are casual and include assistance. No server or account is added.
- Content pages use Helmet metadata/canonical URLs and post-build Chromium prerendering (scripts/prerender.mjs). public/sitemap.xml lists indexable routes. Actual game route /gomoku is noindex; the substantial setup/rules page and guide are indexable. Unknown routes retain actual 404 responses via netlify.toml.
- articles.ts holds guide content; reviewedGuides.ts overrides selected older guides. Current Article renderer supports paragraphs, headings, simple lists and bold, not Markdown links. Game-specific play CTA must point back to the correct setup.
- Tests use Node assert and TypeScript transpilation for pure engines plus existing match verifiers. verify-gomoku.mjs covers rules, illegal actions, replay, overlines, draw, AI immediate tactics, worked guide positions, seeded opening determinism and complete games. Browser checks must also exercise setup, gameplay, keyboard input, results, undo, resume and mobile layouts. Run lint, production build, verify-site and verify-live before/after publication as appropriate.
- The uploaded ZIP has specifications only. The user explicitly authorized independent web implementations after confirming source is unavailable. Do not claim operation-for-operation engine/AI/RNG parity or reuse nonexistent puzzle/word banks. Verify licenses before adding externally sourced assets or dictionaries.
- Ads remain disabled. New games do not imply AdSense approval; the last confirmed decision is Low value content. Do not submit account declarations as part of game releases.

## Reversi architecture addition — 2026-11-03

Reversi uses /reversi-setup and /reversi with slash-normalized setup detection. Its immutable engine records explicit -1 pass actions; the worker performs bounded computer/hint search and is terminated on move/reset/navigation. Undo finds the last human placement including intervening pass actions rather than assuming two alternating placements. New browser keys use dostrike-reversi-*-v1. LocalGameRecords is shared with Gomoku without changing its keys. Both games restore validated histories on reload, and explicit new-game actions clear the previous save. BoardGame.css provides reusable layout primitives for subsequent board games.
